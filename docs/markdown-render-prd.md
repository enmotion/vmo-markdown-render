# markdown-render 产品需求文档

- 版本：v0.1
- 日期：2026-10-22
- 状态：需求基线；首版实现与验证记录见 markdown-render-validation.md
- 项目：vmo-markdown-render

## 1. 产品目标与范围

为 Vue 3 应用提供可定制的 Markdown 展示组件，统一覆盖文档展示和大模型聊天中的流式内容展示。复用现有开源解析及渲染能力，重点建设稳定的对外接口、主题、尺寸、自定义组件和文本转换能力。

产品规划包含两个组件，名称固定为 `markdown-render` 和 `markdown-input`。render 首版需求记录见下文；聊天输入组件的后续实施基线见第 18 节。

`markdown-input` 的早期原位富文本设想已按后续确认调整为聊天源码输入与 mention 标签编辑，不提供外部 Vue 组件注入能力；以第 18 节为准。

## 2. 已确认的核心需求

1. 完整文档和大模型流式 Markdown 使用同一个展示组件。
2. 支持基础 Markdown、常见扩展、代码高亮、公式、Mermaid、脚注和目录。
3. 支持默认 12px 的组件基础字号、内部 em 相对尺寸、亮色与暗色模式、外部 CSS 配置。
4. 支持外部注册 Vue 组件，并在内容中渲染为真实 Vue 组件。
5. 注册组件可以自行请求数据，使用正常的 Vue 生命周期及业务上下文。
6. 提供 primary、warning、info、success、danger 五种语义色；后四种缺失时分别回退到 primary。
7. H1～H6 默认使用 primary，允许统一及逐级覆盖。
8. 支持正则转换规则数组；同一位置首个命中的规则生效，不串行转换，不再次匹配转换结果。

## 3. 使用场景

### 3.1 文档展示

传入完整 Markdown，展示排版、代码、表格、公式、图表、目录和业务组件。内容可以整体替换，组件应正确更新。

### 3.2 大模型聊天

宿主应用负责网络请求和累计文本，持续向组件传入当前完整内容。组件处理未完成语法，尽量保持已展示内容与交互组件稳定，流结束后收敛到完整文档结果。

### 3.3 业务内容扩展

内容包含宿主注册的业务标签，例如商品卡、用户卡或数据卡。组件接收数据属性，可以自行加载数据、展示加载及错误状态，并提供用户交互。

### 3.4 文本转换

宿主配置多条正则规则，将正文中的业务数据转换成展示文本，例如将用户对象转换成其 name。原始 Markdown 始终保留，转换只影响展示。

## 4. Markdown 能力清单

“全部 Markdown”以本清单作为首版验收范围，不表示支持所有方言。

| 类别 | 首版范围 |
| --- | --- |
| 基础语法 | H1～H6、段落、粗体、斜体、引用、有序及无序列表、嵌套列表、分隔线、链接、图片、转义、换行、行内代码、代码块 |
| 常见扩展 | 表格、表格对齐、任务列表、删除线、自动链接 |
| 代码 | 围栏语言识别、语法高亮、复制；未知语言降级为普通代码 |
| 公式 | 行内及块级公式；明确支持的分隔语法，错误时局部降级 |
| 图表 | Mermaid 围栏代码块；错误时保留可读源码或局部错误信息 |
| 脚注 | 定义、引用、跳转与返回 |
| 目录 | 根据标题生成目录、标题锚点、重复标题处理 |
| 提示块 | GitHub Alerts 五类语法及本库约定的别名 |
| 业务组件 | 已注册标签到 Vue 组件的映射 |

补充约束：

- 任务列表为展示态，不直接修改 Markdown。
- 目录插入语法建议为独占一行的 `[TOC]`，并通过事件提供标题信息；属于本库扩展，最终语法在技术验证后定稿。
- 公式建议支持 `$…$` 与 `$$…$$`，需要验证普通货币文本不被误识别。
- 不支持的语法应保留可读内容，单个扩展失败不影响全文。
- 原生 HTML 默认关闭；如提供开启选项，必须安全过滤。此项为首版建议默认值，尚未单独确认。

## 5. 流式展示

### 5.1 输入协议

- `content` 为当前累计完整字符串，不是单次增量片段。
- `streaming` 为 true 表示内容仍在生成，false 表示按完整文档处理；默认 false。
- 不内置 SSE、WebSocket、请求鉴权或自动滚动。
- 支持追加、替换、清空及开始新内容。

### 5.2 行为要求

- 未闭合的强调、链接、代码围栏、公式和组件标签不得导致整篇内容消失或报错。
- 临时语法补全仅用于展示，不改写原始内容。
- 默认等待业务组件标签与属性完整、标签闭合后再挂载，避免使用残缺参数触发请求。
- 后续追加正文时，已完整的业务组件应尽量保持实例与状态。
- 不能简单假设此前所有块永久不变：后出现的引用定义、脚注等可能影响前文，最终结果必须正确。
- Mermaid 等高成本内容采用节流或等待块完成后处理，具体策略通过验证决定。
- 结束后去除临时补全，最终语义与同一原文一次性渲染一致。
- 内容真实变化引起的重新排版允许发生，不承诺绝对无布局变化。

## 6. 内容字号、相对尺寸和响应式

- 内容基础字号使用 px，默认 12px，不修改或依赖宿主 html 根字号；内部相对尺寸使用 em。
- 提供数值型 `fontBaseSize`，单位 px，默认 12 表示 12px，支持正有限数值。非法值回退到 12。
- 字号、间距、内边距等通过统一尺寸变量计算，缩放后正常重新排版。
- 不修改宿主 html 字号，不使用 transform 缩放正文。
- 同页多个实例可以独立缩放。
- 图片不超出容器；宽表格、长代码支持横向滚动。
- 外部 Vue 组件可使用本库尺寸变量，但其固定尺寸不会被自动改写。

## 7. 主题与颜色

### 7.1 主题

- 支持空值、`light`、`dark`、`auto`，默认空字符串，不主动指定主题。
- auto 跟随系统颜色偏好，并响应系统切换。
- 允许同页实例使用不同主题，不依赖全局 dark 类。
- 对外提供独立 CSS 入口、稳定样式类名及 CSS 变量，不要求消费者安装 Tailwind。
- 样式限制在组件容器内；提供无默认主题的使用方式。

### 7.2 语义色及语法映射

| 配置色 | 提示语法 | 含义 |
| --- | --- | --- |
| primary | `> [!IMPORTANT]` | 重要内容 |
| info | `> [!NOTE]` | 说明信息 |
| success | `> [!TIP]` | 建议与技巧；不表示操作已成功 |
| warning | `> [!WARNING]` | 警告与风险 |
| danger | `> [!CAUTION]` | 危险与负面后果 |

建议额外支持本库别名：INFO → info，SUCCESS → success，DANGER / ERROR → danger。这些别名不属于 GitHub 五类 Alerts。

每类提示使用对应颜色的标题、图标和左边框，浅背景由语义色派生，正文使用正常正文色。允许单独覆盖背景和边框。不同类型通过标题与图标区分，即使颜色相同仍可识别。

primary 有内置默认值，具体色值由默认主题设计确定。其他四色未设置时通过 CSS 回退到 primary，而非各自固定的默认色。

### 7.3 普通 Markdown 配色

| 内容 | 默认规则 |
| --- | --- |
| H1～H6 | primary，通过字号、字重和间距区分层级 |
| 链接 | primary |
| 正文、粗体、斜体 | 正文色 |
| 普通引用 | 次级正文色和中性边框 |
| 代码、表格、分隔线 | 独立中性色变量 |
| 代码语法高亮 | 独立亮暗代码主题，不强制映射五种语义色 |

标题回退顺序：该级标题色 → 统一标题色 → primary。

```css
.my-markdown {
  --md-primary: #6366f1;
  /* 以下均可省略 */
  --md-warning: #d97706;
  --md-info: #0284c7;
  --md-success: #16a34a;
  --md-danger: #dc2626;
  --md-heading-color: #1f2937;
  --md-h1-color: #4338ca;
}
```

示例色值不构成默认主题定稿。正文、背景、边框、字体、行高、间距及圆角也应提供配置变量。

## 8. 外部 Vue 组件

### 8.1 注册与内容协议

建议以实例级 `components` 映射注册，避免全局注册污染。标签建议采用小写 kebab-case。

```vue
<markdown-render
  :content="content"
  :components="{ 'product-card': ProductCard }"
/>
```

```markdown
<product-card product-id="123"></product-card>
```

- 仅允许显式注册的标签实例化 Vue 组件。
- 不编译任意 Vue 模板，不执行表达式、v-on、v-bind 或 Markdown 内脚本。
- 标签属性按数据处理；首版建议以字符串属性为基础，不隐式推断复杂 JavaScript 对象。
- 复杂数据通过宿主上下文或后续明确的数据协议传递。
- 未注册组件建议显示转义原文。
- 首版建议支持块级组件；嵌套 Markdown、插槽和行内组件须通过技术验证明确，不默认承诺。
- 标准节点替换可作为独立扩展接口，与业务标签注册分开设计。

以上具体标签和属性协议属于建议设计，核心已确认需求是外部组件注册与正确渲染。

### 8.2 内部请求和业务上下文

- 支持正常 Vue 生命周期、响应式状态、provide/inject 和宿主应用上下文。
- 组件自行调用 fetch 或业务请求工具，处理加载、错误、重试和取消请求。
- 渲染器不代管业务请求，也不承诺对请求自动去重。
- 鉴权由宿主提供，不要求写入 Markdown。
- 真实属性变化是否重新请求由业务组件决定。
- 正文追加不得无故重建已挂载的稳定组件；整个内容被替换或组件被移除时允许卸载。

## 9. 正则转换规则数组

### 9.1 配置结构

名称为 `textRules`，类型为规则数组，不是串行转换管道。

```ts
interface TextRule {
  pattern: RegExp;
  replace: string | ((match: string, ...args: any[]) => string);
}
```

以上为接口草案，正式类型需补齐捕获组、偏移和分组上下文，避免最终公共接口使用 any。

```ts
const textRules = [
  {
    pattern: /\{"id":"[^"]+","name":"([^"]+)"\}/g,
    replace: (_match: string, name: string) => name,
  },
  {
    pattern: /ORDER-(\d+)/g,
    replace: '订单 $1',
  },
];
```

示例正则只覆盖固定格式，不作为任意 JSON 解析器。复杂对象可通过规则回调解析提取。

### 9.2 匹配语义

1. 所有规则面对同一份原始文本，不消费其他规则的转换结果。
2. 从左到右查找匹配；同一起点多规则命中时，数组中靠前的规则胜出。
3. 已消费的匹配区间不再接受其他匹配；与其重叠的候选忽略。
4. 不同位置可以分别命中不同规则；一次命中不会停止全文匹配。
5. 字符串结果作为纯文本插入；支持 replace 回调返回 Vue VNode，或通过 component 与 props 配置渲染组件。输出不再作为 Markdown、HTML 或规则输入解析。
6. “并行”表示规则彼此独立，不要求使用多线程。

例如规则 A 匹配 abc，规则 B 匹配 ab，输入 abc 时采用 A；输入中另一处独立匹配 B 的文本仍可转换。

### 9.3 范围与边界

- 默认处理解析后的普通正文文本节点，跳过代码、链接地址、HTML 属性、组件属性及公式源码。
- 默认不跨 Markdown 节点匹配，规则不能通过拼接不同节点吞掉文档结构。
- 规则命中的对象必须在 Markdown 解析后仍属于同一文本节点；包含强调等特殊字符的复杂数据需验证或采用显式标记格式。
- 正则支持重复查找；不得泄漏或依赖调用方 RegExp.lastIndex 状态。
- 零长度匹配应拒绝或跳过，避免无限循环。
- 流式每次基于原始内容派生，不重复转换已有输出。跨网络分片的文本在累计后可命中。
- 无法对任意正则自动判断匹配是否“完整”，需要宿主规则包含明确结束条件。
- 回调异常时保留命中原文，报告规则错误，其他正文继续渲染。
- 不承诺主线程同步正则的强制超时；需限制处理规模并验证复杂正则性能。
- 本阶段只承诺文本输出，转换成 Vue 组件不属于已确认范围。

## 10. 建议公共接口

| 属性 | 类型 | 默认值/说明 |
| --- | --- | --- |
| content | string | 空字符串，当前完整 Markdown |
| streaming | boolean | false |
| theme | 空字符串 / light / dark / auto | 空字符串 |
| fontBaseSize | number | 12，单位 px |
| components | Record<string, Component> | 空映射，实例隔离 |
| textRules | TextRule[] | 空数组 |
| unstyled | boolean | false，不加载默认主题的具体方式需验证 |

建议事件：链接点击、渲染错误、规则转换错误、标题目录更新。错误应包含阶段与必要位置，避免默认记录完整敏感内容。

```vue
<markdown-render
  :content="markdown"
  :streaming="isGenerating"
  theme="auto"
  :font-base-size="12"
  :components="components"
  :text-rules="textRules"
/>
```

本节为公共 API 草案，不直接透传全部底层引擎配置；验证后根据必要性定稿。

## 11. 技术选型与实现方向

### 11.1 原则

- 不从零编写 Markdown 解析器。
- 优先复用已有 Vue 流式引擎，外部保持本库接口稳定。
- 文本经解析后映射至 Vue 节点；业务组件进入正常 Vue 渲染树。
- 公式、图表、代码高亮尽量按需加载，避免基础展示强制加载全部运行时。
- 主题和尺寸由本库定义，避免公共接口绑定底层 CSS 类。
- 后续输入组件可共享语法约定及主题，不强制共享内部文档模型。

### 11.2 候选方案

| 方案 | 适配判断 | 需要验证或补齐 |
| --- | --- | --- |
| vue-stream-markdown | 优先验证；文档描述增量解析、稳定 Vue 节点、实例组件映射 | 全部约定语法、定制节点、规则接入、rem 与样式控制 |
| markstream-vue | 重点对照；已有流式和丰富节点、自定义组件 | 注册隔离、公开接口适配、样式覆盖及依赖 |
| markdown-it + 自建 Vue 渲染层 | 可控性优先的备选 | 流式语法处理、状态保持、VNode 渲染与插件整合 |
| unified / remark / rehype | AST 扩展完整的备选 | Vue 渲染、流式逻辑和更多集成工作 |

当前仅有文档调研结论，未完成运行验证、性能比较、依赖审查或许可证确认，不能据此宣称最终最佳方案。

### 11.3 验证关卡

1. 在当前 Vue 3、TypeScript、Vite 库环境中构建与消费正常。
2. 全部语法样例可展示，结束态与完整渲染语义一致。
3. 连续追加内容时业务组件挂载次数及状态符合要求。
4. 正则转换可在正文节点阶段接入，不破坏代码或组件属性。
5. 多实例颜色、主题、缩放、组件注册互不干扰。
6. 完成 HTML、链接、Mermaid 和属性的安全样例验证。
7. 记录基础与增强功能构建体积、浏览器兼容、许可证、维护及版本情况。
8. 记录典型长文与高频追加的耗时，确定有测试环境和输入规模依据的性能指标。

若优先候选无法满足关键约束，先比较第二候选，再考虑自行建设渲染层。

## 12. 验收标准

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 基础及扩展语法样例 | 清单内内容展示正确，嵌套结构不丢失 |
| A02 | 每字符或不同大小分片输入 | 无未捕获异常，未完成内容可读，结束态正确 |
| A03 | 已挂载业务组件之后追加正文 | 不无故重新挂载，不重复触发挂载请求，状态保留 |
| A04 | 清空及替换内容 | 旧内容及组件按需移除，无跨内容状态串用 |
| A05 | 两个实例使用不同主题与 fontBaseSize | 独立生效，不改变宿主根字号 |
| A06 | 只配置 primary | 标题、链接及五类提示使用预期颜色；四个可选色回退到 primary |
| A07 | 单独配置 warning 或 H1 色 | 仅对应内容覆盖，其他回退规则不变 |
| A08 | Alerts 五种类型 | 颜色、标题和图标符合映射，普通引用保持普通引用 |
| A09 | 组件自行请求数据 | 宿主上下文可用，正常展示加载、结果和错误 |
| A10 | 两条规则同位置命中 | 数组首条胜出，输出不被后续规则转换 |
| A11 | 不同位置命中不同规则 | 各自转换，代码及属性保持原样 |
| A12 | 正则回调异常或零长度匹配 | 不挂死、不破坏整篇文档，保留原文或跳过并报告 |
| A13 | 公式、Mermaid 错误 | 局部降级，不阻断正文 |
| A14 | 重复标题、脚注、多实例 | 锚点可用，实例间 ID 不冲突 |
| A15 | 窄屏与放大字号 | 图片不溢出，代码和表格可滚动，正文正常换行 |
| A16 | 危险链接、脚本及事件属性 | 不执行，不绕过已注册组件和 HTML 策略 |
| A17 | 真实消费端安装构建产物 | 类型、JS、CSS 及按需增强入口可用 |

## 13. 实施阶段与交付

1. 技术验证：候选引擎、语法语料、状态保持、规则接入、样式控制、体积与兼容报告。
2. 核心实现：markdown-render、基础语法、流式入口、主题、尺寸、自定义组件、textRules。

## 14. 代码组织与可维护性要求

### 14.1 模块职责与依赖方向

按职责拆分模块，禁止将解析、流式处理、主题、规则匹配和业务组件注册集中在一个 Vue 文件中。建议目录如下，实施时可以依据选定引擎调整：

```text
components/markdown-render/
  markdown-render.vue       # 对外组件，组装能力与转发事件
  types.ts                 # 公共属性、事件和扩展接口类型
  composables/             # 实例状态、主题监听、更新调度与生命周期清理
  nodes/                   # 确有定制需求的节点组件
use.lib/markdown/
  engine/                  # 第三方引擎适配与节点转换
  streaming/               # 流式状态和更新策略
  text-rules/              # 正则候选查找、冲突处理与文本替换
  components/              # 注册映射、属性处理和组件节点协议
  extensions/              # 公式、Mermaid、目录等增强能力的接入
  security/                # 链接、HTML 和属性策略
  types/                   # 内部共享协议
styles/markdown/
  tokens.css               # 尺寸、颜色等公共变量
  base.css                 # 基础排版
  themes/                  # 亮色与暗色主题
  extensions/              # 提示块、代码、公式等局部样式
```

- 公共组件依赖内部能力，内部纯逻辑不得反向依赖组件入口。
- 第三方引擎细节集中在适配层，避免类型、调用方式和 CSS 选择器散落到所有模块。
- 实例状态归属实例，避免模块级可变注册表导致多实例污染。
- 只创建实际需要的模块，不为目录完整性建立空文件或无意义的转发层。

### 14.2 代码复用边界

- 主题变量、语法约定、公共类型及与 UI 无关的工具应支持后续 markdown-input 复用。
- 规则匹配、锚点生成和数据校验优先实现为可独立验证的纯函数。
- 静态与流式展示复用同一套语法、节点和主题能力，仅分离更新及临时补全策略。
- 公式、图表和代码高亮各自封装加载、渲染及失败降级逻辑，避免重复实现加载器。
- 只对已有共同职责提取共享代码；不为未来编辑器提前建设大型抽象层，不要求编辑器共享渲染器内部状态模型。
- 类型与运行时策略保持单一来源，避免多处维护同一语义色映射或提示类型表。

### 14.3 文件拆分与复杂度

- 文件围绕单一职责组织，主 Vue 组件只负责输入输出、布局和能力组装。
- 手写源码单文件原则上控制在 300 行以内；超过时必须检查职责并拆分，确有内聚性需要保留时在评审中说明原因。生成文件与固定测试语料不计入。
- 不为满足行数机械切碎函数；复杂匹配、流式调度等应拆成命名清晰、可单独验证的步骤。
- 避免通过大量布尔参数控制互不相关行为，优先使用明确配置类型和职责边界。

### 14.4 注释与维护文档

- 公共属性、事件、类型和扩展接口使用 TSDoc，说明默认值、输入输出、回退行为及必要示例。
- 复杂逻辑注释解释原因和约束，重点覆盖正则优先级与重叠处理、流式完成态收敛、组件身份保持、颜色回退及安全边界。
- 正则注明匹配格式、捕获组含义和已知限制；第三方兼容处理注明对应依赖版本或问题来源。
- 注释默认使用中文，代码标识符采用一致的英文命名；不添加仅复述代码的逐行注释。
- TODO 必须说明具体问题和处理条件；修改代码时同步更新相关注释、接口文档及示例。
- 补充简洁的架构说明，记录模块依赖、关键数据流、如何增加节点/规则/主题，以及最终技术选型的理由和限制。

### 14.5 维护性验收

- 评审确认不存在承载多个独立职责的超大文件；超出建议行数的文件有合理说明。
- 正则规则冲突、流式组件状态、主题回退等关键行为有针对性的测试，测试不依赖底层引擎私有实现。
- 引擎调用集中，公共接口不意外暴露第三方内部类型。
- 新增一种提示类型或调整一个主题变量无需修改多份重复映射。
- 生命周期监听、定时任务和异步资源有明确清理或取消机制。
- 开发者可根据架构说明定位扩展入口，公共 API 注释与实际行为一致。

## 17. 首版实施决策记录

以下为开发验证后的实现选择，取代相应待定技术项，不代表此前已逐项由用户确认：

- 使用 markdown-it 14.3.3 + @markmend/core 流式补全及自有 Vue 节点映射；未使用 vue-stream-markdown 运行时。
- 原生 HTML 保持转义，不提供开启选项；自定义业务标签仅接受注册映射。
- 组件支持字符串属性、成对闭合/自闭合标签、纯文本默认插槽；不提供嵌套业务标签与富文本插槽。

- 基础样式入口 style.css，公式样式入口 math.css，unstyled 禁用默认排版。完整变量及事件见 README 和 markdown-styles.md。
- 产物为 ESM 与 CommonJS，SSR/Nuxt 暂不承诺；性能基线、体积和测试证据见 markdown-render-validation.md。

主题默认空值，组件不添加 .dark 或 data-theme，跟随宿主祖先 .dark；dark/auto 的暗色结果在当前容器添加 .dark。宿主 Tailwind 需采用 class 模式；不操作 html。外部祖先 .dark 不能通过移除实例 class 屏蔽。

## 18. 聊天输入组件实施基线

根据后续确认，markdown-input 面向大模型聊天，以带 mention 标签的 Markdown 源码编辑替代第 1 节原位富文本方向。外部定义多种触发符，参考 Element Plus Mention 的 prefix/options/search/select 设计。mention 是带稳定身份信息的原子标签，可整体删除；不支持图片、视频、音频、文件容器和正文业务组件注入。

使用 version=1 的文字/mention 节点 document 作为 v-model，直接 JSON 保存恢复；发送时导出 document、text 和按出现顺序排列的 mentions。主题、字号、语义色、容器背景和 unstyled 复用 render 模式。Enter 默认发送，可切换 mod-enter 或 none；候选选择与输入法确认优先，代码块 Enter 换行。详细公共协议见 api/markdown-input.md。

### 分类快捷键更新

mention 默认由外部定义的修饰键与单字符键组合唤起，每个组合绑定一个 source 分类，候选严格按分类过滤。默认关闭单字符触发；prefix 仅在显式配置时启用。修饰键与字符键均可配置，快捷键不插入文字，查询选择后替换为带 source 的原子标签。详见 markdown-input API。

### 文本接口升级

公共 v-model 改为字符串，内部 document 不再作为常规组件输出。mentionCodec.decode/encode 负责外部可恢复文本与内部节点转换；getValue/setValue 提供相同编解码边界。submit 与 getText 输出按顺序拼接的发送文字，serializeMention 可定制引用表达。默认保留标记协议包含身份信息，普通 Markdown 保持可读；异常标记保留文字。正常 v-model 回写不重建编辑状态。此项取代第 18 节早期公开 document 的约定。

### 显式转换与添加插槽（2026-10-23）

转换配置采用独立 getter(document) 与 setter(text) 属性，实例提供 getter()/setter(text) 方法。替代 mentionCodec 配置对象，正常 v-model 仍为字符串。添加入口采用 add 命名作用域插槽，右侧操作采用 actions 插槽；库内不默认创建加号、上传按钮或其业务菜单。演示页通过插槽自定义菜单并通过作用域方法唤起引用。

### 输入组件职责收敛（2026-10-24）

markdown-input 仅负责输入、mention 编辑、文本转换与主题，不负责工具栏或发送。移除 add/actions/footer 工具栏插槽、submitOn 属性、submit 事件与方法。Enter 默认换行，仅提供可取消的 enter 编辑事件供宿主接管。演示中的发送按钮、发送快捷键、添加菜单、上传与附件展示均在输入组件外组装。此项取代此前关于工具栏插槽和组件发送策略的约定。

### 双入口与临时过滤更新

mentionTriggers 配置多个单字符与分类，直接输入时前一字符必须为半角空格才展开。组合键入口独立保留、不要求空格。两者打开后使用临时过滤输入，不写入正文或撤销历史；filterOption 可由宿主实现拼音首字母等规则，或通过 search 异步查询。空格退出消费本次空格并清空临时词，提示字符留在正文；Esc 同样取消。选择后字符入口替换提示字符、快捷键入口直接插入标签。停止扫描旧正文唤起，避免退出后继续输入或撤销时误触发。

### 轻量实时排版与列表续项

输入组件支持闭合的粗体、斜体、删除线、行内代码，以及无序/有序列表和引用。编辑所在行显示源码符号，离开后呈现排版；未闭合符号保留原文。不实现表格或媒体。使用现有 markdown-it 解析行内标注，显示层保留源码位置，不改写公共字符串。列表 Enter 自动续项并递增序号、空项退出、Shift+Enter 普通换行，不重排原有编号。enter 事件提供 inList，演示页发送策略尊重列表编辑。mention 数据、临时过滤和输入法优先级不变。

### 始终直接渲染（替代编辑行源码切换）

可识别 Markdown 始终显示排版，光标进入、选中或失焦均不恢复源码。只有编辑破坏结构时无法识别的部分显示原文，恢复有效结构或撤销后重新渲染。删除破坏粗体包裹时不将残缺结构降格为部分斜体。源码仍保留在文本协议中，光标定位须跨过隐藏标记后保持后续输入位置正确。


按最新约定精简输入语法：仅保留星号粗体/斜体、双波浪号删除线、短横线加半角空格无序列表及有序列表。移除下划线强调、代码与引用；加号/星号不再识别为列表或自动续行。反引号不再限制 mention，enter 的兼容字段 inCode 固定 false。本约定取代此前更广的输入语法支持范围；不改变 MarkdownRender。


输入语法进一步移除删除线支持：半角 `~~内容~~` 和全角 `～～内容～～` 均保留普通文字。仅支持星号粗体/斜体、短横线无序列表和有序列表。


节点协议更新：内部文本为 {type:"text",content:string}，mention 为 {type:"mention",content:{label,id,type?,data?}}。默认 getter/v-model 输出数组，文字保留节点结构，mention 展平为 {label,id,type?}，不包含 data、不进行 URI 编码；默认 setter 恢复相同数组，字符串按纯文字导入。转换函数均可省略，getText 独立返回按 label 拼接的文字。此约定取代早期默认字符串编码协议。


Input 文案配置采用 i18n?: `Partial<InputI18n>`，中文默认文案以 KV 保存在内部，computed 合并宿主覆盖。undefined 不覆盖，空字符串覆盖；placeholder 属性优先。所有界面/辅助名称及转换错误提示均读取合并结果；动态切换不改变输入状态。语言选择、业务内容及插槽翻译由宿主负责，不引入 locale。


Input 候选定位配置：placement(auto/top/bottom) 与 offset(px) 控制桌面/光标浮窗，自动避让视口边界；mobilePlacement 默认 bottom-sheet，600px 及以下从底部向上展开，也可设为 caret。底部面板适配安全区、visualViewport 软键盘和减少动态效果设置，不改变内容与 mention 协议。


默认发送字符串更新：getText() 按原顺序将 mention 转为 {label,id,type?} 的 JSON 原文，与普通正文直接拼接；省略 data，不加内部节点包装，不做 URI 编码。默认纯文本复制使用相同表达。getter/setter 的数组协议保持不变，serializeMention 可定制，发送行为仍由宿主执行。
